# 潜在低分规则优化分析

## 1. 结论摘要

当前 `potential-low-v1` 的主要问题不是漏识别，而是圈选范围过宽：Precision 14.87%、Recall 87.86%、F1 25.44%，4,915 条预测低分中有 4,184 条为 FP。

经代码与结果联合检查，主要原因有三项：

1. **最终门槛过低。** 任一风险类型达到 3 分即判潜在低分，而一条 strong 证据就是 3 分。
2. **结构化事实被当成不满意结论。** 流量资源超用、限速加包、退订或降档发生率高，但不必然导致客户给低分。
3. **同一规则跨月/跨事件重复累计。** 例如连续多月 `DATA_USAGE_OVER_RESOURCE`会重复累加 3 分；频次影响应由专门的重复规则表达，而不是让同一规则无限增分。

## 2. v1 离线门槛试验

以下试验只读取既有 `rule_validation_detail.csv`，没有重新读取 Excel。它用于选择候选决策门槛，不代表 v2 的最终验证结果。

| 决策策略 | 预测数 | Precision | Recall | F1 | Lift |
| --- | ---: | ---: | ---: | ---: | ---: |
| v1：命中任意 1 类 | 4,915 | 14.87% | 87.86% | 25.44% | 1.15 |
| 总风险分不低于 10 | 3,511 | 16.66% | 70.31% | 26.94% | 1.28 |
| 总风险分不低于 20 | 2,073 | 20.31% | 50.60% | 28.98% | 1.57 |
| 至少命中 2 类 | 2,428 | 19.03% | 55.53% | 28.34% | 1.47 |
| **至少命中 3 类** | **1,153** | **25.24%** | **34.98%** | **29.32%** | **1.95** |
| 至少命中 4 类 | 600 | 31.00% | 22.36% | 25.98% | 2.39 |
| 总风险分不低于 40 | 622 | 27.81% | 20.79% | 23.80% | 2.14 |

在当前单月样本上，“至少命中 3 类”的 F1 最优；相对 v1，Precision 提升 10.37 个百分点，FP 从 4,184 降至 862，但 Recall 降低 52.88 个百分点。因此不应只保留一个二元名单，而应输出优先级分层。

## 3. 已实施的 v2 优化

规则版本升级为 `potential-low-v2`：

- 同一用户、风险类型、`rule_code`只取一次最高分；多条原始记录仍保留在证据文件中，但不重复抬高类型分。
- 频次只由 `REPEAT_COMPLAINT`、`REPEAT_PLAN_CHANGE`、`REPEAT_SUBSCRIPTION`、`FREQUENT_NEGATIVE_CONTACT`等专门规则计分。
- `high`：至少命中 3 个独立风险类型，`is_potential_low=1`。
- `medium`：命中 2 类，作为二次核验名单。
- `watch`：命中 1 类，只表示风险事实或线索。
- `none`：未命中任何类型。
- CLI 新增 `--potential-low-min-types`和`--medium-priority-min-types`，门槛可随冻结规则版本保存。

分层避免把高召回观察池直接当作高置信潜客。业务资源有限时先处理 high；需要尽量覆盖时再纳入 medium/watch。

## 4. 下一轮验证要求

v2 改变了评分聚合逻辑，必须重新生成独立目录并比较 v1/v2：

```powershell

  --input "doc\指标汇总.xlsx" `
  --output "data\potential-low\20260901-v2" `
  --as-of "2026-09-02" `
  --rule-version "potential-low-v2" `
  --potential-low-min-types 3 `
  --medium-priority-min-types 2
```

验收时至少比较：

| 指标 | 目标方向 |
| --- | --- |
| Precision、F1、Jaccard、Lift | 高于 v1 |
| FP 数、预测低分率 | 明显低于 v1 |
| Recall | 记录下降幅度，并由业务确定最低可接受值 |
| high/medium/watch 各层真实低分率 | 应呈 high > medium > watch |
| 分月指标 | 不应只在某一个月有效 |

## 5. 仍需进一步优化的规则

1. 流量超套：将单月资源超用降为观察证据；连续多月超套、高超套费用或叠加负面文本后再升级。
2. 套餐资费：普通退订、降档、重复订购不单独代表不满；优先要求资费负面文本或短期异常组合。
3. 投诉：单次普通投诉保留观察层；未解决、重复投诉和高频负面触点进入高优先级。
4. 采用分层而非单一准确率目标。高优先级层优化 Precision，中优先级层平衡 F1，观察层保留 Recall。

## 6. 为可靠定版仍需的信息

当前文件足以完成 v2 的同批次回溯验证，但不足以证明规则可跨批次泛化。建议补充：

1. 至少 3-6 个调查月份或独立批次，用于时间外验证。
2. 精确调研时间；当前只有月份时只能以月初截断，可能丢失调研前的当月证据。
3. `gprs_used_v`、`gprs_total`及流量超套费用的单位和业务口径。
4. 投诉处理状态、解决时间、是否重复工单；否则“未解决”只能依赖文本推断。
5. 业务可接受的最低 Recall、目标 Precision及每月可处理名单量，用于选择 high 门槛。
6. 若允许采用监督算法，需要多个历史月份，并按月份切分训练/验证；不能随机拆分同一月份后宣称泛化效果。
