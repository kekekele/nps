# 潜在低分客群规则识别设计

## 1. 目标与适用范围

本方案适用于与示例文件具有相同 Sheet、列名和字段含义的任意批次数据。文件名、记录数、月份范围和具体取值可以变化；示例数据仅用于确认数据结构，不固化人数、比例或阈值结论。

输出：

1. 潜在低分用户及风险分。
2. 用户的主要风险类型、次要风险类型和证据。
3. 每类用户相对其他用户及全量用户的特征画像。

规则只使用判断时点之前的数据。问卷评分、子问题和 Q99 只用于历史规则校准与效果验证，不用于待识别用户打分。

## 2. 数据使用边界

| Sheet | 可用信息 | 在规则中的用途 | 不允许的推断 |
| --- | --- | --- | --- |
| 基础指标 | 年龄、在网时长、终端、套餐费用、地域等 | 用户画像、弱背景证据 | 不能仅凭年龄、终端或套餐贵判定低分 |
| 家庭指标 | 宽带号、带宽、小区、资费、主付费人、流量 | 家庭关系和家宽背景 | 低带宽不能单独等同体验差 |
| 近半年指标 | 月度 ARPU、用量、套内资源、超套费、状态等 | 超套、使用变化和趋势证据 | 数值异常不直接等同“不满意” |
| 业务订购 | 订购类型、资费名称、操作/到期时间、渠道 | 订购、退订及短期重复操作事件 | 无客户意见文本，不能匹配“办不了、未告知”等语义 |
| 投诉明细 | 时间、投诉节点、工单号、明细 | 投诉类型、重复投诉及投诉文本证据 | 没有标准解决状态，不能把普通投诉直接判为未解决 |
| 资费变更 | 变更前后费用、升/降/平移、生失效及办理时间 | 降档、费用变化和频繁变更证据 | 无客户意见文本，不能单独判定资费不满 |
| 限速与加包 | 业务类型、办理时间、加速包代码和名称 | 限速/加包次数及近期性证据 | 无意见文本，不能单独判定流量不满 |
| 狼号 | 通话时长、接触时间、类型 | 特定接触次数和近期性 | 无问题内容，不能归因到具体不满类型 |
| 触点轨迹 | 时间、触点类型/小类、投诉类型、节点、明细、投诉明细、转写、AI提炼、问题/情绪分类 | 触点次数、类别、负面情绪及文本规则 | 仅对真实文本列执行正则 |
| AI感知总结 | 触点明细、AI感知总结、短板 | 辅助画像或规则复核 | 无时间列；未证明生成时间早于判断时点时，不参与打分 |
| 测评明细 | Q1-Q5、Q98、N1、子问题、Q99 | 历史标签、规则校准和原因核验 | 不进入潜在低分用户的规则证据 |

文本正则只作用于：

- `投诉明细`：投诉节点、明细。
- `触点轨迹`：触点类型、触点小类、投诉类型、节点、明细、投诉明细、小热线工单/来电明细、客户转写、AI提炼、问题分类、情绪分类。
- `AI感知总结`：仅在具备可靠数据截止时间时使用触点明细、AI感知总结、短板。

## 3. 处理闭环

```mermaid
flowchart LR
    A[固定结构的批次文件] --> B[字段校验与清洗]
    B --> C[判断时点前证据提取]
    C --> D[分类型规则评分]
    D --> E[用户主次类型与证据清单]
    E --> F[类型用户画像]
    F --> G[历史问卷标签验证]
    G --> H[冻结规则阈值和版本]
```

次数、费用、变化幅度的候选阈值可由历史校准样本的 P75/P90 产生，但不能随每个待识别批次重新漂移。阈值经历史低分/非低分标签验证后冻结到规则版本；新批次只执行规则并监控分布变化。

## 4. 风险类型与真实数据规则

用户允许命中多个类型。规则应先生成证据，再汇总类型分。

### 4.1 投诉未解决疑似型

示例数据没有投诉解决状态，因此只能识别“疑似未解决”。满足任一强证据：

- `投诉明细.明细` 或 `触点轨迹`文本明确命中“未解决、仍未处理、再次投诉、重复投诉、多次反映仍未处理”等。
- 同一用户在 30/90 天内，按标准化后的投诉节点或投诉类型出现重复投诉。

只有单次投诉时归为“投诉高风险型”，不能标记为未解决。

### 4.2 家宽体验风险型

强证据必须来自 `投诉明细` 或 `触点轨迹`：家宽实体词与故障词同时出现。

- 家宽实体：宽带、家宽、光猫、路由器、WiFi。
- 故障表现：断网、掉线、无法上网、网速慢、卡顿、故障、维修未恢复。

`家庭指标.带宽/是否主付费人/宽带流量`、`近半年指标.宽带资费费用`用于画像或增强证据，不能单独判定体验落后。

### 4.3 流量超套风险型

这是结构化数据可直接支持的事实型风险：

- `近半年指标.流量超套费用 > 0`。
- `近半年指标`中技术字段 `gprs_used_v > gprs_total`，即第二个“流量使用量”大于“套内流量资源”，前提是两列单位已确认一致。不能误用前一个同名“流量使用量”（技术字段 `mou`）。
- `限速与加包`在观察窗内存在办理记录，或次数达到冻结阈值。

若同时在投诉/触点文本命中“流量不够、超套扣费、限速、加包”等，才升级为“流量超套不满型”。

### 4.4 套餐资费不满疑似型

强证据来自投诉/触点文本：“套餐贵、资费贵、性价比低、收费不合理、违约金、优惠到期”等。

结构化增强证据：

- `资费变更.变更标识（0：平移；1：升档；-1：降档） = -1`。
- 观察窗内多次资费变更。
- `业务订购.订购类型`为退订，或短期同类业务反复订购/退订。
- 变更后费用下降。

主套餐费用高或单次降档不能单独证明不满意，只能作为背景或中弱证据。

### 4.5 办理/变更/退订受阻疑似型

语义证据只能来自投诉/触点文本：“无法办理、办不了、无法退订、强制绑定、限制条件、流程复杂、未告知”等。

`业务订购`和`资费变更`只提供操作时间、类型、资费和渠道，可用于识别短期重复操作；不能在这些 Sheet 上执行受阻语义正则。

### 4.6 营销宣传争议型

仅使用投诉/触点文本或问题分类，匹配“夸大宣传、与实际不符、隐瞒限制、诱导、未经同意、不知情开通”等。若只有营销类触点而无争议文本或负面情绪，只作为弱证据。

### 4.7 提醒告知不足疑似型

强证据：投诉/触点文本命中“未提醒、提醒不及时、未告知收费”等，并且同一观察窗存在流量超套费用。

仅有超套费时归入“流量超套风险型”，不能推断一定未提醒。

### 4.8 高频触点负面型

- `触点轨迹.情绪分类`为负向，且负向触点次数达到冻结阈值。
- 30/90 天触点次数达到阈值，同时客户转写或 AI 提炼存在负面问题。

普通触点次数多但没有负面信息时，只记录“高频触点”，不判为负面型。

## 6. 类型评分与归属

规则字典配置证据等级，不在代码中散落阈值：

```python
type_score = 3 * strong_count + 2 * medium_count + weak_count
```

- `primary_type`：超过类型阈值后，标准化类型分最高的类型。
- `secondary_types`：其他超过各自阈值的类型。
- 并列时依次比较强证据数、最近证据时间。
- 同一事件的同类型多次正则命中只计一次。
- 缺失数据与零次事件分开；覆盖不足输出“证据不足”。
- “风险型”可由结构化事实命中；“不满/未解决型”必须有对应文本或重复事件证据。

## 7. 阈值校准与通用运行

落地前必须满足以下数据条件：

- 事件时间按源格式显式解析：兼容 Excel 日期、`YYYYMMDD`、`YYYYMMDDHHMMSS` 和标准日期时间字符串；解析后的年份必须落在批次合理业务区间。
- 文本证据在源 Sheet 清洗后、详情哈希前提取。仅保存规则命中片段或受控证据引用，不把完整敏感文本写入普通分析文件。
- 同名列按列位置和第二行技术字段共同识别；表头结构不符时中止相应规则，不猜测映射。
- 每个 Sheet 分别记录最早/最晚业务时间，判断是否覆盖所需的 30/90/183 天窗口。

历史批次：

1. 以每张问卷的调研月份为判断时点，回看前 30/90/183 天。
2. 生成规则证据和类型分，与实际低分/非低分标签对照。
3. 对候选阈值输出样本数、精确率、召回率、提升度及月份/地区稳定性。
4. 选定阈值并保存 `rule_version`，不能根据当前批次结果临时改阈值。

待识别批次：使用最近数据截止月作为统一判断时点，应用已冻结规则。若 Sheet 缺失、列变化或时间覆盖不足则停止对应类型计算并报告，不能默认无风险。

## 8. 类型用户画像

每个类型比较三组：该类型用户、其他潜在低分用户、全量用户。

- 基础：年龄、性别、地域、在网时长、终端、套餐费用。
- 家庭：是否家庭、宽带号关联、是否主付费人、带宽、宽带资费和宽带流量。
- 行为：ARPU、用量、超套费、投诉、触点、变更、限速和加包。
- 输出：用户数、占比、覆盖率、缺失率、分布、中位数、效应量、FDR 和提升度。

高基数类别设置最小样本量，小样本合并为“其他”；不根据单个批次的极少数用户给出类型结论。

### 9.1 `potential_low_user.csv`

粒度为用户 + 判断时点，每个用户一行：

| 字段 | 说明 |
| --- | --- |
| `customer_key` | 源脱敏手机号规范化后的用户键 |
| `as_of` | 本次规则判断截止时间 |
| `total_risk_score` | 所有已命中风险类型分之和 |

| `primary_type` | 类型分最高的主要风险类型 |
| `secondary_types` | 其他命中类型，以 `|` 分隔 |
| `hit_type_count` | 命中的风险类型数 |
| `rule_version` | 冻结的规则版本 |
| `data_coverage_rate` | 本批次可用规则数据 Sheet 数/要求的 Sheet 数；不是字段非空率 |

### 9.2 `potential_low_user_type.csv`

| 字段 | 说明 |
| --- | --- |
| `customer_key`、`risk_type` | 用户及风险类型 |
| `type_score` | 该类型证据分之和 |
| `evidence_count` | 去重后的规则代码数 |
| `strong_count` | 强证据条数 |
| `latest_evidence_time` | 最近证据时间 |
| `is_hit` | 类型分是否达到 `type_threshold` |
| `rule_version`、`as_of` | 规则版本及判断时点 |

### 9.3 `potential_low_evidence.csv`

粒度为用户 + 去重证据，是解释结果的审计明细：

| 字段 | 说明 |
| --- | --- |
| `customer_key`、`risk_type` | 证据归属用户和风险类型 |
| `rule_code` | 稳定的规则代码 |
| `evidence_level`、`points` | strong/medium/weak 及对应 3/2/1 分 |
| `source_sheet`、`source_column`、`source_row_no` | 证据来源位置；窗口聚合证据标记为“窗口聚合” |

| `evidence_value` | 次数、费用、差值、类别或 `regex_hit` |
| `evidence_excerpt` | 文本命中附近的最小片段；非文本证据为空 |

### 9.4 `potential_low_type_profile.csv`

粒度为风险类型 + 对比客群 + 特征/特征值：

- `cohort` 包括 `type_users`、`other_potential_low`、`all_users`。
- `feature_type` 区分 numeric/categorical；`feature_value`仅类别特征使用。
- `user_count`、`missing_rate`描述覆盖。
- `value_count`、`value_rate`描述有效值数或类别分布。
- `mean`、`median`用于数值特征。
- `effect_size`为数值特征标准化均值差，`lift`为类别在类型用户中的占比相对全量占比。
- `p_value`和`fdr`用于显著性判断，不单独作为业务因果结论。

### 9.5 验证文件

`rule_validation_detail.csv`为问卷粒度匹配明细：

| 字段 | 说明 |
| --- | --- |
| `survey_id`、`customer_key`、`survey_month` | 调研流水号、用户键和验证判断月 |
| `actual_segment`、`actual_low` | 《测评明细》产生的真实 low/non_low 及 1/0 标记 |
| `predicted_low` | 按该问卷时点之前证据识别的潜在低分标记 |
| `match_result` | `TP`正确识别低分、`FP`误识别、`FN`漏识别、`TN`正确排除 |
| `total_risk_score`、`primary_type`、`secondary_types`、`hit_type_count` | 当时的规则结果和解释 |
| `rule_version` | 验证使用的规则版本 |

`rule_validation.csv`为指标汇总，`survey_month=ALL`表示全周期，其余行用于观察月度稳定性；`risk_type=ALL`表示总体识别，其余行表示该类型对真实低分的识别能力。字段包括样本数、真实低分/非低分数、预测数、TP/FP/FN/TN、precision、recall、specificity、accuracy、F1、Jaccard、真实/预测低分率和 lift。

### 9.6 规则、质量与清单

- `rule_dictionary.csv`：规则代码、数据源、条件或正则、证据等级、次数阈值和规则版本。
- `batch_quality.csv`：各 Sheet 的可用状态、读取行数和异常消息。Sheet 不可用不能解释为用户无风险。
- `manifest.json`：生成时间、输入文件、判断时点、完整规则参数以及每个输出文件的行数和 SHA-256。

所有用户、类型和证据结果保留 `customer_key`，保证“识别用户—解释类型—查看证据—分析画像—历史验证”可以完整回溯。

## 10. 与《测评明细》真实低分客群的匹配验证

### 10.1 真实标签与验证粒度

- 验证粒度是 `调研流水号`，不是去重后的客户。一个客户多次调研分别验证。
- Q1-Q5、Q98、N1 中任一有效分数为 1-6，则 `actual_low=1`；所有有效分数均为 7-10，则为 0；全部无效时不参与验证。
- 预测结果只使用该问卷调研月份之前 183 天内的证据。问卷评分、子问题和 Q99 不进入规则输入，防止标签泄漏。
- 当前源字段按调研月份验证，统一使用月份起点作为截止时点，因此不会使用调研当月后续行为。若后续提供精确调研时间，可直接改为精确时点。

### 10.2 匹配关系

| 结果 | 真实标签 | 规则识别 | 含义 |
| --- | --- | --- | --- |
| TP | 低分 | 潜在低分 | 成功覆盖的真实低分问卷 |
| FP | 非低分 | 潜在低分 | 规则误识别，需检查规则精度或标签时差 |
| FN | 低分 | 非潜在低分 | 漏识别，需检查数据覆盖或缺失风险类型 |
| TN | 非低分 | 非潜在低分 | 正确排除 |

### 10.3 核心指标

$$
Precision=\frac{TP}{TP+FP},\quad Recall=\frac{TP}{TP+FN}
$$

$$
F1=\frac{2\times Precision\times Recall}{Precision+Recall},\quad
Jaccard=\frac{TP}{TP+FP+FN}
$$

$$
Specificity=\frac{TN}{TN+FP},\quad Accuracy=\frac{TP+TN}{TP+FP+FN+TN}
$$

$$
Lift=\frac{Precision}{\text{全体验证问卷真实低分率}}
$$

匹配度建议以 F1 和 Jaccard 为主，precision、recall 分别解释误识别与漏识别，lift 判断规则是否优于按总体低分率随机圈选。低分占比较低时不能只看 accuracy。

### 10.4 验证与调优流程

1. 先检查 `batch_quality.csv`及问卷、事件的时间覆盖，覆盖不足的月份不参与阈值定版。
2. 查看 `rule_validation.csv`中 `ALL/ALL`总体结果，再比较各月份稳定性和各风险类型贡献。
3. 从 `rule_validation_detail.csv`抽取 FP/FN，通过 `customer_key`关联证据明细，复核误识别和漏识别原因。
4. 只在历史校准批次调整正则、证据等级及阈值；在独立验证批次确认后冻结新 `rule_version`。
5. 报告指标时同时给出问卷数、真实低分率和数据覆盖，不能只报告单一匹配率。
